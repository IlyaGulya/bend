# Self-host parser architecture: current boundary and historical graph

## IR specifications

This file records the parser migration history. The compiler's checked-FIR and backend-IR boundaries are specified separately:

- [`FIR_LAWS.md`](./FIR_LAWS.md) — what `Checked.CheckedProgram` guarantees (ownership, publication, signatures, occurrences, failure), what it does not, and the open proof obligations.
- [`BIR_LAWS.md`](./BIR_LAWS.md) — the lowering contract and `BIR.Program` well-formedness, consuming FIR as specified in `FIR_LAWS.md`.

At baseline `f640d74948c5db9f6b2298db721327b61f894711`, the main grammar SCC contained **161 functions**. Its demonstrated shortest do-expression cycle was `parse_do_return → parse_do_return_scan → parse_term → parse_atom → parse_atom_scan → parse_do_atom → parse_do_atom_args_result → parse_do_atom_colon → parse_do_return`. This is a cross-boundary cycle through the shared expression parser, not an isolated do-scanner recursion.

**Decision:** a local do scanner is insufficient. A separate expression parser returns a remainder that Bend cannot prove decreases relative to the do driver's input: `driver(after, ...)` fails with “expected: a decreasing self-call” even when that parser consumes a token. Use the generated, typed Request/Kont feedback cut, not a handwritten whole-parser migration, arbitrary fuel, or unchecked same-token recursion. The checkpointed canonical intrinsic repairs are recorded below; parity/span differences remain untouched.

### Explicit generated effects

`evals/parser_full_explicit_progress.ts` rewrites the same typed Body/LTerm AST that is rendered and executed. `Progress` has exactly `NoProgress` and `Consumed`; composition is OR. Mechanical active use of a structurally matched declared token-list tail emits a consumption witness. Head inspection and an ignored tail capture do not. Hidden `FeedbackCursorWitness` fields preserve deferred activation through typed Kont capture/resume; metadata births and inherited copies are not consuming operations.

`FeedbackControl.progress` retains cumulative semantic consumption; `own_progress` records the current synchronous step's fresh effect. `FeedbackResume` preserves both. This prevents an old saved `Consumed` from being charged again as a newly consumed input cell. Semantic ASTs, cursor values, spans and diagnostics remain payloads, not evidence inferred from returned remainder identity.

Source head ownership is transferred at active calls and checked by binder/constructor structure. Cursor-returning calls receive neutral ownership, not new consumption credit; locals, products and projections retain it. Reconstructing a nonempty token cursor inside driver-reachable code, reusing a transferred cursor, overlapping active captures, unsupported foreign callback/import ABIs and unsupported conditional retirement stop instrumentation. Nonempty cursor construction and cursor-producing imports are allowed in initialization definitions outside actual dispatch/resumer reference reachability; first-class producers are rejected.

Declared callback telescopes append `FeedbackCursorWitness` inputs after semantic arguments. A lambda activates the transferred witness only on active cursor use; ignoring or inspecting its head stays `NoProgress`. Semantic callback transporters carry hidden input witnesses through ordinary helpers. Named callback references adapt to the same typed ABI. Partial callbacks with live deferred ownership require a proved single terminal local invocation; escaping or repeated activation is rejected.

`evals/parser_full_explicit_machine.ts` evaluates emitted writer packets and the generated runtime ABI together. It keeps values/effects correlated and pops the actual matching continuation rather than connecting shared child Outcomes to unrelated callers.
